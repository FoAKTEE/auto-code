## What was built
- **`zkqec.sandbox`**: frozen bwrap profiles `agent-call/{claude,codex}` and `program` (unshare user/pid/ipc/uts/net/cgroup, new session, die-with-parent, clearenv + allowlist, private /proc and /dev, read-only root). `nsexec.py` is a stdlib-only pre-exec helper. It creates a user+mount namespace and mounts one size-limited private tmpfs for home, /tmp, work and out. It copies the credential into the fresh home (0600), applies rlimits, runs bwrap, and copies out only regular files under caps. `cgroup.py` provides the campaign slice, per-job scopes (RuntimeMaxSec, MemoryMax, TasksMax, no swap), and `DeadlineSupervisor`. `runner.py` runs a job with byte-capped stdio and kills the job when the broker fails it closed. `outputs.py` has the trusted-side caps.
- **`zkqec.broker`**: the mitmproxy addon (stdlib + mitmproxy only) and `policy.py` (pure decision logic, also unit-tested). Each campaign has its own CA. The addon:
  - allowlists exact (host, method, anchored path) triples;
  - inspects bodies, frames and tool declarations;
  - enforces ceilings, the dispatch switch and the deadline;
  - writes a sanitized JSONL log, fsync'ed before forwarding;
  - records usage from SSE and `response.completed` frames.

  `bridge.py` is the host side of the socat bridge: a Unix socket that injects the per-job token into CONNECT. `launcher.py` handles grants and the log, and `testing.py` is a local TLS fake upstream. Base policy: `configs/broker/policy.json`. Declared prices: `configs/broker/prices.json`.
- **`zkqec.agents.launch`**: `claude_call` / `codex_call` argv, env and home-layout builders. **`zkqec.qualify.main(argv)`**: 35 properties, each with a positive and a negative test. The lead still has to wire `zkqec qualify-host`.

## Deviations (and why)
1. bwrap 0.6.1 has no `--size`. `nsexec` mounts the size-limited tmpfs instead. Credentials only ever exist in that private tmpfs (never on disk) and vanish with the job's namespace.
2. Jobs are identified by a per-job Proxy-Authorization token. A Python host bridge injects it, so the sandbox never sees it and other local users can't use the broker. Inside the sandbox it is still socat.
3. A `quiet_block` class covers the observed telemetry and discovery endpoints. They get 403 without failing the job; anything else not allowlisted fails the job closed.
4. The broker is stricter than spec. It allowlists top-level body keys per provider, message/input item and part types, and frame types. It logs key names and input "shape" (types, roles, sizes), never values.
5. Codex: the role contract goes through `model_instructions_file` (Codex has no `--system-prompt`). `SSL_CERT_FILE` is the broker CA only (stricter; works). The Claude prompt is passed on stdin.
6. Outputs come back by capped collection from the tmpfs, not through a host rw bind. `/etc/alternatives` is bound read-only (otherwise `awk` and similar links dangle).

## Residual risks
- Server-side model metadata can add Codex tools remotely. The broker catches this, but only by blocking the call.
- CPUQuota is unenforced: the user manager is delegated only `memory pids`.
- Codex frames carry no output-token field (ceiling unenforceable) and Codex has no declared price.
- OAuth refresh endpoints are not allowlisted. An expired token makes calls fail closed (the user's tokens never rotate), so credential freshness has to be managed. The Claude access token had about 4.5 h left at the run.
- Body-key allowlists are pinned to the current CLI versions; a CLI upgrade fails closed until requalified.
- Same-uid host processes can reach a job's bridge socket.
- The broker sees plaintext and credentials (it is part of the TCB).
- The empty parent `zkqec.slice` persists.

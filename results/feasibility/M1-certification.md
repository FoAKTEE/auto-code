# M1 measured certification feasibility tables

Contracts §C1: measured on this host for the production L2 entry point (`zkqec.verify.distance` 1.1.0, pipeline adapter `l2.distance` 1.1.0), commit `2ec95728f8cc`. Generated by `scripts/feasibility_tables.py --mode full`; the JSON next to this file holds every row.

## Host and method

- **Host:** Intel(R) Xeon(R) Platinum 8360Y CPU @ 2.40GHz, 144 logical CPUs (72 physical cores, 2 sockets), 503 GiB RAM; Linux-5.15.0-176-generic-x86_64-with-glibc2.35.
- **Software:** CPython 3.10.22, numpy 2.2.6, scipy 1.15.3; kernel `kernel-0.1.0+1`; measured sources dirty: False.
- **Runs:** one fresh subprocess per (code, t, sector); BLAS/OpenMP pools pinned to one thread; at most 32 children at once, with the sum of their preflight memory estimates ≤ 240 GiB. Per-case caps: memory estimate ≤ 64 GiB (≤ 16 GiB for non-flagship codes), M ≤ 250M, kernel `max_pairs` = 2G, predicted CPU ≤ 900 s per sector.
- **Columns:** CPU and wall time cover the `certify_distance` call only, including its fixed per-call part (row reduction, CSS check, canonical basis, code hash, witness re-check). Peak RSS is the child's `ru_maxrss` minus its RSS just before the call. For small cases this delta has a floor of about 10–17 MB, which comes from transient allocations during interpreter start-up, not from the call. Pairs is the kernel's counter of same-syndrome pairs examined. `ok` means the run completed and certified the interval shown. `pairs>cap` means the kernel's pair cap stopped the run (`budget_exhausted`, unknown). `skip` means the preflight estimate exceeded the measurement caps, so the case was not run.
- **Total measurement:** 21.4 min wall; 2.97 CPU-hours over 850 child processes; largest child peak RSS 34.02 G.
